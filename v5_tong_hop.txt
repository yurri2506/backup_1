================================================================================

  • Sử dụng SABV5 (Secure Aggregated Block Verification 5)
  • Sử dụng LMTR4 (Local Merkle Tree Rebalancing Algorithm 4)

📊 LÝ DO 8 THREADS NHANH HƠN:
  1. Optimal thread count: 8 threads = 50% số cores (optimal)
  2. Ít contention: 8 threads trên 16 cores → contention thấp
  3. Cache efficiency: Cache sharing tốt với 8 threads
  4. Overhead thấp: Thread synchronization overhead thấp
  5. Memory access pattern: Memory access pattern hiệu quả

📊 LÝ DO 16 THREADS CHẬM HƠN:
  1. Contention cao: 16 threads trên 16 cores → contention cao
  2. Cache misses: Cache sharing kém hiệu quả với 16 threads
  3. Overhead cao: Thread synchronization overhead cao
  4. Memory access pattern: Memory access pattern kém hiệu quả
  5. Parallelization overhead: Amdahl's Law - parallelization có giới hạn
